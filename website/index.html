§ 01 — THE PRIVACY CONTINUUM

Privacy is a spectrum, not a switch.

Every transaction chooses its level — transparent when it must be, fully private by default when it can be. No one is forced to disclose; compliance paths exist only where explicitly chosen. Level 2 is the default for base-layer value movement.

0
Transparent

Public transaction, like Ethereum. For regulated flows and audited transfers that must be public.

1
Optional Shielding

The user chooses when to enter and exit the privacy pool. The bridge between public and private.

2
Default Strong

Private by default on the base layer; opting out is explicit. The default for value movement.

3
Private Compute

Confidential contract state and ZK execution on the EVMs. Programmable privacy, not just transfers.

§ 02 — ARCHITECTURE

Three layers, one key hierarchy.

A Monero-inspired base layer for settlement, two specialized private EVMs, and shared components that keep every layer in the same anonymity set. One seed controls all accounts.

EVM.01
Seraph EVM
General-purpose private EVM — Solidity-compatible, gas in SER, optional private contract state.
  • Privacy continuum per transaction
  • Precompiles for privacy primitives
Phase 1 · MVP
EVM.02
XMR EVM
XMR-optimized EVM — preferential XMR fees and tight base-layer coupling for XMR flows.
  • Pay fees in XMR via relayers
  • Bridged XMR representation
Phase 2 · Alpha
Shared layer
Unified key hierarchy · shared anonymity sets

One seed derives accounts on every layer. Note pools are shared where possible, bridges are trust-minimized (lock → prove → mint), and a relayer network provides gas abstraction so users can pay in XMR or SER on either EVM.

Notes from the base layer and both EVMs are designed to contribute to common privacy pools where cryptographically feasible. Full shared-set guarantees are a core research goal, not yet a shipped guarantee.

§ 05 — ROADMAP

From PoC to mainnet.

Honest, phase-gated delivery. Nothing ships before its exit criteria pass — and the earlier phases deliberately exclude features that don't belong yet.

Phase 0 · PoC · 2–4 months · in progress
Private transfers work end-to-end.

Note system, ZK spend circuit, CLI wallet, single-node base layer with in-process P2P, and an XMR simulation. Exit: two users privately transfer value, double-spends rejected, amounts confidential.

Phase 1 · MVP · 4–8 months
A usable testnet with wallet, explorer, one EVM.

Multi-node base-layer testnet, Seraph EVM v1, audited PrivacyPool + SER token, reference wallet, explorer, and bridge. Exit: 100+ testnet users, 10K+ transactions.

Phase 2 · Alpha · 3–6 months
The dual-EVM architecture proves out.

XMR EVM v1, cross-EVM bridge, messaging, AI payments, stablecoin prototype, gas abstraction, TypeScript SDK. Audits begin. Exit: all modules deployed, 500+ testnet users.

Phase 3 · Beta · 4–8 months
Mainnet candidate. Production modules.

Genesis config, production modules, full TS/Rust/Go SDKs, relayer network, audits complete, liquidity plan, governance bootstrap. Exit: bug bounty live, 5+ relayers, liquidity secured.

Phase 4 · v1.0 Mainnet
Production launch and stabilization.

Base layer + both EVMs + all bridges, progressive deposits, professional relayers and validators, explorer v1, governance transition. Exit: 20+ validators, no critical incidents.

§ 06 — SECURITY & PRIVACY MODEL

Private by construction.

The privacy guarantees come from cryptography, not policy. Here is exactly how each class of attack is handled, and what we commit to before any mainnet.

No mainnet until two independent audits + formal verification of the core circuits are complete.

Anonymity-set depletion

Shared note pools across layers plus full-chain membership proofs (FCMP++) keep the set large and mixin-free.

Nullifier guessing

Domain-separated nullifier derivation from secret spend keys — a nullifier reveals nothing about which note it came from.

Amount overflow

Bulletproofs++ range proofs guarantee values are in range and non-negative inside the proof itself.

Key reuse

Stealth addresses and one-time keys — every output note has a fresh destination key.

Bridge theft

Fraud proofs and bond-and-challenge on every lock → mint path across layers.

Oracle manipulation

Time-weighted, decentralized oracles with delay and challenge windows.

  • Selective disclosureIncoming view keys scan for received notes; optional outgoing view keys prove a nullifier was spent by a party — compliance without breaking default privacy.
  • AuditsTwo independent security audits before mainnet, plus formal verification of core ZK circuits.
  • FuzzingFuzz testing of all contracts and circuits, continuous monitoring post-launch.
  • Bug bountyAudit-grade bounty covering base-layer consensus, EVM circuits, and first-party modules — rewards in SER + XMR.

FAQ
When does the presale go live?

The launch date and final terms are announced here. Nothing is sold until the contracts are deployed and this page is wired to them.

How do I participate?

Connect a wallet (MetaMask, WalletConnect, or Phantom) when the sale opens, choose a tier, approve the payment, and buy. Strategic and Private tiers require an allowlisted address; Public is open.

What are the fees?

A 0.5% presale fee is applied on each purchase and goes to treasury. Post-TGE, a 1% transfer tax applies on non-exempt transfers — 50% auto-burned, 50% to treasury.

What happens at TGE?

Strategic and Private buyers receive 25% / 20% of their allocation at TGE, with the remainder vesting linearly over 12 months after a 14-day cliff. Public buyers receive 100% at TGE.

Is this private?

The presale itself is a public token sale on-chain. Seraph's privacy guarantees apply to the base layer and private pools, which are separate phases of the roadmap. We do not collect identity data — participation is address-based.

How is the 100M SER supply allocated?

Per the whitepaper: ecosystem & community 40%, team & advisors 20% (4-year vest, 1-year cliff), foundation/treasury 15%, early contributors 15%, public sale + initial liquidity 10%. This presale offers only the 25M earmarked for early contributors and the public sale — the other 75M is not for sale.

Is this related to the Seraph ARPG game?

No. Seraph Protocol is an unrelated privacy-blockchain research project. Any similarity in name is coincidental.

When is mainnet?

No date is set. Mainnet requires the Phase 3–4 exit criteria — including two independent audits and formal verification of the core circuits — which gate every launch.

Can I run a node or contribute?

Yes — the project is open-source on GitHub and contributors are welcome. Nodes arrive with the testnet phase (Phase 1).
